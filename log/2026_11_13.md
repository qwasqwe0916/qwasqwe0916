## 기능 개발 (3단계 ⑤ 지원 시스템 + 팀 구성·팀 페이지)

오늘 한 일: ⑤ 지원 시스템 → 수락 후 연락 방법 논의 → 팀 구성·팀 페이지·연락 링크 추가

---

### 1. ⑤ 지원 시스템

#### 결정 사항 (11/10에 정리한 추천안대로 진행)
* 마감일이 지난 글은 지원 차단
* 모집 인원을 넘는 수락만 차단 (자동 마감 없음, 모집 상태는 작성자가 변경)
* 거절된 사람은 재지원 불가 (중복 지원 방지 R17 그대로)
* 모집완료가 되어도 대기 중인 지원은 그대로 둠
* 지원 메시지는 선택 (300자 이하)
* 위쪽 메뉴에 "마이페이지"를 따로 만듦

#### 서버 (`server/src/routes/applications.js`)
* `POST /api/posts/:id/applications`: 지원하기
  * 본인 글, 모집완료 글, 마감일이 지난 글은 400 / 이미 지원한 글은 409 (UNIQUE 위반 처리)
* `GET /api/posts/:id/applications`: 지원자 목록 (작성자만, R20)
  * 지원자의 이름, 학과, GitHub, **보유 기술 스택 전체** (지원자 ID로 기술 스택 조회)
* `PATCH /api/applications/:id`: 수락 / 거절 / 대기로 되돌리기 (작성자만, 모집 인원 초과 수락 차단)
* `DELETE /api/applications/:id`: 지원 취소 (지원자 본인, 대기 상태일 때만, R22)
* `GET /api/me/posts`: 마이페이지 - 내가 쓴 글과 글별 지원 수·대기 수·수락 수 (LEFT JOIN + GROUP BY)
* `GET /api/me/applications`: 마이페이지 - 내 지원 현황 (R21)
* 게시글 상세에 지원 수, 수락 수, 내 지원 정보(`myApplication`), 마감일 지남 여부(`isExpired`) 추가

#### 화면
* 게시글 상세
  * 작성자가 아닌 사람: 지원 영역 (지원 메시지 + [지원하기] → 내 지원 상태, 대기일 때 [지원 취소])
    * 모집완료·마감일 지남·로그인 안 함일 때는 안내 문구
  * 작성자: 지원자 관리 (수락 / 모집 인원 / 지원 수, 지원자별 기술 스택·메시지·GitHub, [수락] [거절] [대기로 되돌리기])
  * 모집 인원 옆에 수락·지원 수, 마감일이 지나면 "마감일 지남" 표시
* 마이페이지 (`/mypage`)
  * "내가 쓴 글" 탭: 글별 지원 수, 수락 / 모집 인원, 새 지원(대기) 수
  * "내 지원 현황" 탭: 지원한 글, 내 지원 상태, 작성자

### 2. 수락 후 연락 방법 논의
* 비교한 방안: 학교 이메일 공개, 모집 글의 연락 링크, 프로필 연락처, 팀 페이지, 사이트 내 쪽지, 실시간 채팅, 수락 알림 메일
* 오픈채팅방 자동 생성
  * 카카오톡은 오픈채팅방 생성·초대 기능을 외부 개발자에게 제공하지 않아 불가
  * 디스코드는 봇으로 채널 자동 생성이 가능하지만, 서버·봇 준비와 디스코드 계정 필요 등 부담이 커서 제외
* 다른 연락 수단 검토: Slack, 인스타그램 DM, 에브리타임, 노션, 텔레그램·라인 → 카카오톡·디스코드로 충분하다고 판단
* **결정**
  * 연락 링크(선택)를 메인으로 하고, 카카오톡 오픈채팅·디스코드 링크만 허용 (위험한 링크에 대한 책임 문제 예방)
  * 수락만으로는 공개하지 않고 **[팀 구성하기]로 확정한 뒤** 공개 (실수로 수락했을 때 대비)
  * 링크가 없어도 연락할 수 있게 **팀 페이지**(학교 이메일 + 팀 게시판)
  * 작성자도 지원자 이름을 눌러 프로필을 볼 수 있게 (수락 전에도 가능)

### 3. 팀 구성·팀 페이지·연락 링크 (R27 ~ R29)
* 지원자 프로필 보기
  * 지원자 관리 목록은 한눈에 보이게 그대로 두고, 지원자 이름을 누르면 프로필 화면
  * `GET /api/applications/:id/applicant` (글 작성자만, 수락 전에도 가능, 이메일은 제외)
* 팀 구성하기 (R27)
  * 지원자 관리 아래 [팀 구성하기], 수락 1명 이상이면 가능 (모집 인원과 달라도 됨)
  * 확인 창에 구성 결과 안내 → 글은 모집완료, 대기 중인 지원은 자동 거절, 이후 지원 상태·다시 모집중으로 변경 불가
  * `POST /api/posts/:id/team` (트랜잭션 + 게시글 행 잠금으로 중복 구성 방지)
  * 익명 글 작성자 실명 공개(R26) 시점을 **수락 → 팀 구성 후**로 변경
  * 수락됐지만 팀 구성 전인 지원자에게는 "작성자가 팀을 구성하면 팀 페이지가 열립니다" 안내
* 팀 연락 링크 (R28)
  * 글쓰기·수정 화면에 선택 입력 + "넣어 두면 팀원 간 연락이 원활해진다"는 안내 문구
  * **카카오톡 오픈채팅(`open.kakao.com/o/...`)과 디스코드 초대(`discord.gg/...`, `discord.com/invite/...`)만 허용**
  * 주소를 분해해 https, 도메인 정확히 일치, 경로 형식을 검사 (위장 도메인, 다른 경로, 포트, 사용자 정보가 붙은 주소 차단)
  * 링크는 공개 응답에 넣지 않음 (작성자에게는 수정 화면용으로만, 팀원에게는 팀 페이지에서)
* 팀 페이지 (`/posts/:id/team`, R29): 작성자와 수락된 팀원만
  * 연락 링크 + "외부 서비스로 이동합니다. 개인정보나 금전 요구에 주의" 문구
  * 팀원 목록: 이름, 역할(작성자/팀원), 학과, **학교 이메일**, GitHub, 기술 스택
  * 팀 게시판: 팀원끼리만 보는 글 쓰기·본인 글 삭제 (`GET/POST /api/posts/:id/team/messages`, `DELETE /api/team-messages/:id`)
  * 링크가 없으면 작성자에게 링크 등록 안내
* 게시글 상세: 팀원에게 "팀 페이지로 가기", 팀 구성 후 모집 상태 변경 버튼 숨김, 팀이 있는 글 삭제 시 경고
* 마이페이지: "팀 구성됨" 표시
* DB: `posts.contact_link`, `posts.team_formed_at` 컬럼, `team_messages` 테이블 추가
  * 팀원 테이블은 따로 만들지 않고 "작성자 + 수락된 지원자"로 판단 (같은 정보를 두 곳에 저장하지 않음)

### 테스트
* 클라우드 (가짜 Supabase + MySQL)
  * 지원: 중복 지원 409, 모집완료·마감일 지남·본인 글 지원 400, 메시지 300자 초과 400, 남의 글 지원자 목록·처리 403, 수락된 지원 취소 400, 남의 지원 취소 403, 모집 인원 초과 수락 차단
  * 링크 검사 14가지 (허용 4, 차단 10: 다른 도메인, 위장 도메인, http, 다른 경로, 포트, 사용자 정보, javascript: 등)
  * 팀: 수락 0명 팀 구성 400, 중복 구성 409, 팀 구성 후 상태 변경 400, 팀원이 아닌 사람의 팀 페이지 403, 남의 팀 게시판 글 삭제 403, 게시글 삭제 시 팀 게시판 함께 삭제
  * 두 계정 브라우저: 잘못된 링크 차단 → 지원 → 지원자 프로필 → 수락(아직 익명, 팀 페이지 없음) → 팀 구성 → 실명 공개·팀 페이지 → 팀 게시판 대화
* 로컬 (실제 Supabase + 학교 메일 계정 + 테스트 계정): 지원부터 팀 페이지까지 전체 흐름 확인 완료
