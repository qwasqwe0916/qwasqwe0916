## 기능 개발 (3단계 ⑤ 지원 시스템)

### 결정 사항 (11/10에 정리한 추천안대로 진행)
* 마감일이 지난 글은 지원 차단
* 모집 인원을 넘는 수락만 차단 (자동 마감 없음, 모집 상태는 작성자가 변경)
* 거절된 사람은 재지원 불가 (중복 지원 방지 R17 그대로)
* 모집완료가 되어도 대기 중인 지원은 그대로 둠
* 지원 메시지는 선택 (300자 이하)
* 위쪽 메뉴에 "마이페이지"를 따로 만듦

### 서버 (`server/src/routes/applications.js`)
* `POST /api/posts/:id/applications`: 지원하기
  * 본인 글, 모집완료 글, 마감일이 지난 글은 400 / 이미 지원한 글은 409 (UNIQUE 위반 처리)
* `GET /api/posts/:id/applications`: 지원자 목록 (작성자만, R20)
  * 지원자의 이름, 학과, GitHub, **보유 기술 스택 전체** (지원자 ID로 기술 스택 조회)
* `PATCH /api/applications/:id`: 수락 / 거절 / 대기로 되돌리기 (작성자만)
  * 수락 인원이 모집 인원에 도달하면 추가 수락 차단
* `DELETE /api/applications/:id`: 지원 취소 (지원자 본인, 대기 상태일 때만, R22)
* `GET /api/me/posts`: 마이페이지 - 내가 쓴 글과 글별 지원 수·대기 수·수락 수 (LEFT JOIN + GROUP BY)
* `GET /api/me/applications`: 마이페이지 - 내 지원 현황 (R21)
* 게시글 상세에 지원 수, 수락 수, 내 지원 정보(`myApplication`), 마감일 지남 여부(`isExpired`) 추가
* 익명 글 작성자 실명 공개 (R26)
  * 수락된 지원자에게만 게시글 상세, 작성자 프로필, 내 지원 현황에서 작성자 실명 공개
  * 그 외 사람(비회원, 대기·거절된 지원자)에게는 계속 "익명"

### 화면
* 게시글 상세
  * 작성자가 아닌 사람: 지원 영역 (지원 메시지 + [지원하기] → 내 지원 상태, 대기일 때 [지원 취소])
    * 모집완료·마감일 지남·로그인 안 함일 때는 안내 문구
    * 수락되면 "익명 작성자의 실명이 공개되었습니다" 안내
  * 작성자: 지원자 관리 (수락 / 모집 인원 / 지원 수, 지원자별 기술 스택·메시지·GitHub, [수락] [거절] [대기로 되돌리기])
  * 모집 인원 옆에 수락·지원 수, 마감일이 지나면 "마감일 지남" 표시
* 마이페이지 (`/mypage`)
  * "내가 쓴 글" 탭: 글별 지원 수, 수락 / 모집 인원, 새 지원(대기) 수 표시
  * "내 지원 현황" 탭: 지원한 글, 내 지원 상태, 작성자 (익명 글은 수락된 경우에만 실명)
* 요구사항 R16, R17, R20에 결정 사항 반영

### 테스트
* API: 지원, 중복 지원 409, 모집완료·마감일 지남·본인 글 지원 400, 메시지 300자 초과 400, 남의 글 지원자 목록·처리 403, 수락된 지원 취소 400, 남의 지원 취소 403
* 익명 글: 대기 중에는 "익명", 수락 후 상세·작성자 프로필·내 지원 현황에서 실명 공개, 비회원에게는 계속 "익명"
* 두 계정 브라우저 테스트: 지원 → 작성자 화면에 지원자와 기술 스택 표시 → 수락 → 지원자 화면에 실명 공개 → 모집 인원 초과 수락 차단 → 마이페이지 두 탭 확인

### 팀 구성·팀 페이지·연락 링크 (⑤ 이후 추가 요구사항)
* 논의: 수락 후 연락 방법 비교 (이메일, 연락 링크, 프로필 연락처, 팀 페이지, 쪽지, 실시간 채팅, 알림 메일)
  * 오픈채팅방 자동 생성은 카카오톡이 외부에 기능을 제공하지 않아 불가, 디스코드는 봇으로 가능하나 부담이 커서 제외
  * 결정: **연락 링크(선택)를 메인으로, 링크가 없어도 연락할 수 있게 팀 페이지(이메일 + 팀 게시판)**
* 지원자 프로필: 지원자 관리 목록은 그대로 두고, 지원자 이름을 누르면 프로필 화면 (수락 전에도 가능)
  * `GET /api/applications/:id/applicant` (글 작성자만)
* 팀 구성하기 (R27)
  * 수락만으로는 아무것도 공개되지 않고, 작성자가 [팀 구성하기]를 눌러야 팀이 확정됨 (실수로 수락했을 때를 대비)
  * 조건: 수락 1명 이상 (모집 인원과 달라도 됨)
  * 구성하면 글은 모집완료, 대기 중인 지원은 자동 거절, 이후 지원 상태·다시 모집중으로 변경 불가
  * `POST /api/posts/:id/team` (트랜잭션 + 게시글 행 잠금으로 중복 구성 방지)
  * 익명 글 작성자 실명 공개(R26) 시점을 **수락 → 팀 구성**으로 변경
* 팀 연락 링크 (R28)
  * 글쓰기·수정 화면에 선택 입력, "넣어 두면 팀원 간 연락이 원활해진다"는 안내 문구
  * **카카오톡 오픈채팅(`open.kakao.com/o/...`)과 디스코드 초대(`discord.gg/...`, `discord.com/invite/...`)만 허용**
  * 주소를 분해해 https, 도메인 정확히 일치, 경로 형식을 검사 (위장 도메인, 다른 경로, 포트, 사용자 정보가 붙은 주소 차단)
  * 링크는 공개 응답에 넣지 않음 (작성자에게는 수정 화면용으로만, 팀원에게는 팀 페이지에서)
* 팀 페이지 (`/posts/:id/team`, R29): 작성자와 수락된 팀원만
  * 연락 링크 + "외부 서비스로 이동합니다. 개인정보나 금전 요구에 주의" 문구
  * 팀원 목록: 이름, 역할(작성자/팀원), 학과, **학교 이메일**, GitHub, 기술 스택
  * 팀 게시판: 팀원끼리만 보는 글 쓰기·본인 글 삭제
  * 링크가 없으면 작성자에게 링크 등록 안내
* 게시글 상세: 팀원에게 "팀 페이지로 가기", 수락됐지만 팀 구성 전인 지원자에게 안내 문구, 팀 구성 후 모집 상태 변경 버튼 숨김, 팀이 있는 글 삭제 시 경고
* 마이페이지: "팀 구성됨" 표시
* DB: `posts.contact_link`, `posts.team_formed_at` 컬럼, `team_messages` 테이블 추가
  * 팀원 테이블은 따로 만들지 않고 "작성자 + 수락된 지원자"로 판단 (정규화)
* 문서: 요구사항 R20·R26 수정, R27~R29 추가, ERD·정규화 문서 갱신
* 테스트
  * 링크 검사 14가지 (허용 4, 차단 10: 다른 도메인, 위장 도메인, http, 다른 경로, 포트, 사용자 정보, javascript: 등)
  * 수락 0명 팀 구성 400, 중복 구성 409, 팀 구성 후 상태 변경 400, 팀원이 아닌 사람의 팀 페이지 403, 남의 팀 게시판 글 삭제 403, 게시글 삭제 시 팀 게시판 함께 삭제
  * 두 계정 브라우저: 잘못된 링크 차단 → 지원 → 지원자 프로필 → 수락(아직 익명, 팀 페이지 없음) → 팀 구성 → 실명 공개·팀 페이지 → 팀 게시판 대화
