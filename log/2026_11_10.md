## 기능 개발 (3단계 ① 로그인·프로필)

### 서버 (`server/`)
* Supabase 로그인 토큰 검증 미들웨어 작성 (`src/middleware/auth.js`)
  * `authenticate`: 요청마다 토큰을 검증하고 MySQL `users`에서 회원 조회
  * `requireAuth`(로그인 필요), `requireUser`(로그인 + 프로필 필요)
* 내 정보 API (`src/routes/me.js`)
  * `GET /api/me`: 내 프로필 조회, 프로필이 없으면 404 (`PROFILE_REQUIRED`)
  * `POST /api/me`: 첫 로그인 시 프로필 생성, `@seoultech.ac.kr` 도메인 검사 (토큰의 이메일 기준)
  * `PUT /api/me`: 내 프로필 수정
  * 이름(필수, 50자), 학과(50자), GitHub 주소(`https://github.com/`로 시작) 입력값 검사
* 공통 오류 처리 추가

### 화면 (`client/`)
* `react-router-dom` 추가, 화면 주소 구성
* 로그인 상태와 프로필을 앱 전체에서 관리 (`AuthProvider`)
* 로그인 화면: 학교 이메일 입력 → 인증번호 입력 (다시 받기, 이메일 다시 입력)
* 프로필 등록(첫 로그인)·수정 화면
  * 로그인했지만 프로필이 없으면 어느 화면에서든 프로필 등록 화면으로 이동
* 토큰을 자동으로 붙이는 API 호출 함수 (`src/lib/api.js`)
* Vite 기본 템플릿 화면 제거, 기본 스타일 적용

### 테스트
* 클라우드 환경에서 가짜 Supabase 서버 + MySQL로 전체 흐름 확인
  * 타 도메인 차단, 잘못된 인증번호, 프로필 등록, 새로고침 시 로그인 유지, 프로필 수정, 로그아웃
  * API: 토큰 없음·잘못된 토큰 401, 타 도메인 프로필 생성 403, 중복 생성 409
* 로컬에서 실제 학교 메일로 인증번호 로그인 → 프로필 등록까지 확인 완료

### 문제 해결
* 인증번호 요청 시 "Load failed" 오류
  * 원인: `.env`의 Supabase 주소에 불필요한 경로가 붙어 있었음 (`https://xxxx.supabase.co` 뒤에는 아무것도 없어야 함)
  * Safari의 "Load failed"는 브라우저가 서버에 접속하지 못했다는 네트워크 오류
* 메일에 인증번호 대신 링크가 표시됨
  * 원인: 실제로 사용되는 메일 템플릿에 `{{ .Token }}`이 아닌 링크 코드가 남아 있었음
  * 처음 가입은 **Confirm sign up**, 이미 가입된 경우는 **Magic link** 템플릿을 사용하므로 두 템플릿 모두 수정
  * 메일 제목으로 어떤 템플릿이 쓰였는지 구분할 수 있음
* Supabase 대시보드 설정 변경은 서버·화면 재실행이 필요 없고, `.env` 변경은 재실행이 필요함
