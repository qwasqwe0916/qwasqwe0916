## 기능 개발 (3단계 ① ~ ④)

오늘 한 일: ① 로그인·프로필 → 프로필 화면 개선·회원 탈퇴 → ② 게시글 CRUD → 테스트 계정·익명 게시 → ③ 기술 스택 → ④ 댓글

---

### 1. ① 로그인·프로필
* 서버
  * Supabase 로그인 토큰 검증 미들웨어 (`src/middleware/auth.js`)
    * `authenticate`: 요청마다 토큰을 검증하고 MySQL `users`에서 회원 조회
    * `requireAuth`(로그인 필요), `requireUser`(로그인 + 프로필 필요)
  * `GET /api/me`: 내 프로필 조회, 프로필이 없으면 404 (`PROFILE_REQUIRED`)
  * `POST /api/me`: 첫 로그인 시 프로필 생성, `@seoultech.ac.kr` 도메인 검사 (토큰의 이메일 기준)
  * `PUT /api/me`: 내 프로필 수정
  * 이름(필수, 50자), 학과(50자), GitHub 주소(`https://github.com/`로 시작) 입력값 검사, 공통 오류 처리
* 화면
  * `react-router-dom` 추가, 로그인 상태와 프로필을 앱 전체에서 관리 (`AuthProvider`)
  * 로그인 화면: 학교 이메일 입력 → 인증번호 입력 (다시 받기, 이메일 다시 입력)
  * 프로필 등록 화면: 로그인했지만 프로필이 없으면 어느 화면에서든 이동
  * 토큰을 자동으로 붙이는 API 호출 함수 (`src/lib/api.js`), Vite 기본 템플릿 화면 제거
* 로컬에서 실제 학교 메일로 인증번호 로그인 → 프로필 등록까지 확인

### 2. 문제 해결
* 인증번호 요청 시 **"Load failed"**
  * 원인: `.env`의 Supabase 주소에 불필요한 경로가 붙어 있었음 (`https://xxxx.supabase.co` 뒤에는 아무것도 없어야 함)
  * Safari의 "Load failed"는 브라우저가 서버에 접속하지 못했다는 네트워크 오류 (Chrome에서는 "Failed to fetch")
* 메일에 인증번호 대신 **링크만 표시**
  * 원인: 실제로 쓰이는 메일 템플릿에 `{{ .Token }}` 대신 링크 코드가 남아 있었음
  * 처음 가입은 **Confirm sign up**, 이미 가입된 경우는 **Magic link** 템플릿을 쓰므로 둘 다 수정
  * 메일 제목으로 어떤 템플릿이 쓰였는지 구분 가능
* **테스트 계정 로그인 실패** ("Invalid login credentials")
  * 계정을 지우고 **Create new user + Auto Confirm User**로 다시 만들어 해결
* **한글 깨짐**: MySQL 클라이언트의 접속 문자셋이 latin1이면 `mysql < seed.sql`로 넣은 한글이 깨짐 → SQL 파일 3개에 `SET NAMES utf8mb4;` 추가
* 정리: Supabase 대시보드 설정 변경은 재실행이 필요 없고, `.env` 변경은 서버·화면 재실행이 필요함

### 3. 프로필 화면 개선 및 회원 탈퇴
* 위쪽 메뉴의 내 이름 링크를 **"프로필"**로 변경
* 프로필 화면(`/profile`): 보기 상태 → [수정하기] → 입력칸 → [저장하기] / [취소]
* 회원 탈퇴 (R23 신설, 제외 범위에서 삭제)
  * [탈퇴하기] → 확인 창 → `DELETE /api/me`
  * MySQL 회원 삭제 + Supabase 로그인 계정 삭제를 트랜잭션으로 처리 (계정 삭제 실패 시 MySQL 삭제도 되돌림)
  * Supabase 계정 삭제용 `service_role` 키는 `server/.env`에만 보관
* DB: `users`를 참조하는 FK 4개에 `ON DELETE CASCADE` 적용

### 4. ② 게시글 CRUD
* 서버
  * `GET /api/categories`, `GET /api/posts` (최신순, 카테고리·모집 상태 필터, 비회원 조회 가능), `GET /api/posts/:id`
  * `POST /api/posts` (카테고리, 제목 100자, 내용 5000자, 모집 인원 1 ~ 100명, 마감일 형식 검사)
  * `PUT`, `PATCH .../status`, `DELETE /api/posts/:id`: 작성자만 가능 (아니면 403)
  * 마감일(DATE)은 문자열 그대로 받도록 설정 (시간대 변환으로 날짜가 하루 밀리는 문제 방지)
* 화면
  * 메인을 게시글 목록으로 변경: 카테고리 탭, "모집중만 보기", 글쓰기 버튼(로그인 시)
  * 게시글 상세: 작성자에게만 [모집완료로 변경 / 모집중으로 변경], [수정], [삭제], 삭제 전 확인 창
  * 게시글 작성·수정 화면 (남의 글 수정 화면 접근 차단)

### 5. 테스트 계정 및 익명 게시
* 개발 모드 전용 테스트 계정 로그인
  * 로그인 화면 아래 "개발용: 테스트 계정으로 로그인" (이메일 + 비밀번호), `npm run dev`에서만 표시
  * 테스트 계정 `ctm-test-01@seoultech.ac.kr`을 Supabase에서 비밀번호로 생성 (메일 발송 없음)
  * 두 계정을 동시에 쓰려면 브라우저를 두 개(또는 일반 창 + 시크릿 창) 사용
* 익명 게시글 (R24)
  * 글쓰기·수정 화면의 "익명으로 올리기", 수정 시 변경 가능
  * 이름 대신 "익명"으로 표시, 학과는 공개
  * 서버가 익명 글의 작성자 이름·ID를 응답에서 제외하고, "내 글인지"는 `isMine`으로 전달
* 작성자 프로필 보기 (`/posts/:id/author`, R15): 실명 글은 이름·학과·GitHub·기술 스택, 익명 글은 학과·기술 스택만
* DB: `posts.is_anonymous`, `comments.is_anonymous` 컬럼 추가
* 요구사항 추가: R24(익명 게시), R25(익명 댓글), R26(익명 글 작성자 실명은 수락된 지원자에게만 공개)

### 6. ③ 기술 스택
* 서버
  * `GET /api/skills`
  * 프로필 생성·수정 시 보유 기술 저장 (회원 정보와 한 트랜잭션), `GET /api/me`에 보유 기술 포함
  * 게시글 작성·수정 시 필수/선택 기술 저장 (한 트랜잭션, 수정 시 기존 태그 교체)
  * 게시글 목록·상세에 기술 포함 (목록은 한 번의 쿼리로 모든 글의 태그 조회)
  * 기술 필터 `GET /api/posts?skills=3,10`: 선택한 기술 중 하나라도 요구하는 글 (`EXISTS` 서브쿼리)
  * 검사: 존재하지 않는 기술, 같은 기술 중복 선택, 최대 30개
* 화면
  * 프로필 등록·수정·보기에 기술 스택 (칩을 눌러 선택/해제)
  * 글쓰기·수정: 기술 칩을 누를 때마다 필수 → 선택 → 해제
  * 목록에 기술 태그(필수: 진한 태그, 선택: 점선 태그)와 "기술로 찾기", 상세에 필수/선택 기술 구분
  * 폼 안의 체크박스가 세로로 깨지던 레이아웃 수정

### 7. ④ 댓글
* 서버
  * `GET /api/posts/:id/comments` (오래된 순, 누구나), `POST /api/posts/:id/comments` (1000자, 익명 선택)
  * `DELETE /api/comments/:id`: 본인 댓글만 (R14)
  * `GET /api/comments/:id/author`: 댓글 작성자 프로필 (익명이면 학과·기술 스택만)
  * 게시글·댓글 작성자 프로필을 공통 함수로 정리 (`src/profiles.js`)
* 익명 표시 규칙 (R25)
  * 익명 글의 작성자가 그 글에 단 댓글은 체크와 관계없이 **"익명(작성자)"**
  * 그 외 익명 댓글은 글마다 처음 익명 댓글을 단 순서대로 **"익명1", "익명2"…** (같은 사람은 같은 번호)
  * 익명 댓글의 응답에는 이름·회원 ID를 넣지 않음
  * 익명 번호는 현재 댓글 기준으로 매기므로, 앞쪽 익명 댓글이 삭제되면 번호가 바뀔 수 있음
* 화면: 게시글 상세 아래 댓글 목록·작성·삭제, "익명으로 작성" (익명 글 작성자 본인은 체크 고정 + 안내 문구)
