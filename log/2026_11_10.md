## 기능 개발 (3단계 ① 로그인·프로필, ② 게시글 CRUD)

### 서버 (`server/`)
* Supabase 로그인 토큰 검증 미들웨어 작성 (`src/middleware/auth.js`)
  * `authenticate`: 요청마다 토큰을 검증하고 MySQL `users`에서 회원 조회
  * `requireAuth`(로그인 필요), `requireUser`(로그인 + 프로필 필요)
* 내 정보 API (`src/routes/me.js`)
  * `GET /api/me`: 내 프로필 조회, 프로필이 없으면 404 (`PROFILE_REQUIRED`)
  * `POST /api/me`: 첫 로그인 시 프로필 생성, `@seoultech.ac.kr` 도메인 검사 (토큰의 이메일 기준)
  * `PUT /api/me`: 내 프로필 수정
  * 이름(필수, 50자), 학과(50자), GitHub 주소(`https://github.com/`로 시작) 입력값 검사
* 공통 오류 처리 추가

### 화면 (`client/`)
* `react-router-dom` 추가, 화면 주소 구성
* 로그인 상태와 프로필을 앱 전체에서 관리 (`AuthProvider`)
* 로그인 화면: 학교 이메일 입력 → 인증번호 입력 (다시 받기, 이메일 다시 입력)
* 프로필 등록(첫 로그인)·수정 화면
  * 로그인했지만 프로필이 없으면 어느 화면에서든 프로필 등록 화면으로 이동
* 토큰을 자동으로 붙이는 API 호출 함수 (`src/lib/api.js`)
* Vite 기본 템플릿 화면 제거, 기본 스타일 적용

### 테스트
* 클라우드 환경에서 가짜 Supabase 서버 + MySQL로 전체 흐름 확인
  * 타 도메인 차단, 잘못된 인증번호, 프로필 등록, 새로고침 시 로그인 유지, 프로필 수정, 로그아웃
  * API: 토큰 없음·잘못된 토큰 401, 타 도메인 프로필 생성 403, 중복 생성 409
* 로컬에서 실제 학교 메일로 인증번호 로그인 → 프로필 등록까지 확인 완료

### 문제 해결
* 인증번호 요청 시 "Load failed" 오류
  * 원인: `.env`의 Supabase 주소에 불필요한 경로가 붙어 있었음 (`https://xxxx.supabase.co` 뒤에는 아무것도 없어야 함)
  * Safari의 "Load failed"는 브라우저가 서버에 접속하지 못했다는 네트워크 오류
* 메일에 인증번호 대신 링크가 표시됨
  * 원인: 실제로 사용되는 메일 템플릿에 `{{ .Token }}`이 아닌 링크 코드가 남아 있었음
  * 처음 가입은 **Confirm sign up**, 이미 가입된 경우는 **Magic link** 템플릿을 사용하므로 두 템플릿 모두 수정
  * 메일 제목으로 어떤 템플릿이 쓰였는지 구분할 수 있음
* Supabase 대시보드 설정 변경은 서버·화면 재실행이 필요 없고, `.env` 변경은 재실행이 필요함

### 프로필 화면 개선 및 회원 탈퇴 추가
* 위쪽 메뉴의 내 이름 링크를 **"프로필"**로 변경
* 프로필 화면(`/profile`)을 보기 전용으로 변경
  * 이메일, 이름, 학과, GitHub(새 탭 링크), 가입일 표시
  * [수정하기] → 입력칸으로 전환, [저장하기] / [취소]
* 회원 탈퇴 기능 추가 (요구사항 R23 신설, 제외 범위에서 삭제)
  * [탈퇴하기] 클릭 시 확인 창으로 한 번 더 확인
  * `DELETE /api/me`: MySQL 회원 삭제 + Supabase 로그인 계정 삭제
  * Supabase 계정 삭제가 실패하면 MySQL 삭제도 되돌림 (트랜잭션)
  * Supabase 계정 삭제에는 `service_role` 키가 필요 → `server/.env`에만 보관
* DB: `users`를 참조하는 FK(`user_skills`, `posts`, `comments`, `applications`)에 `ON DELETE CASCADE` 적용
  * 탈퇴한 회원의 글이 삭제되면 그 글의 기술 태그, 댓글, 지원 내역도 연쇄 삭제
* 테스트: 보기 → 수정 → 취소/저장, 탈퇴 확인 창 취소/확인, 탈퇴 후 로그아웃 및 MySQL 삭제, 계정 삭제 실패 시 롤백 확인

### ② 게시글 CRUD
* 서버
  * `GET /api/categories`: 카테고리 목록
  * `GET /api/posts`: 게시글 목록 (최신순, 카테고리·모집 상태 필터, 비회원 조회 가능)
  * `GET /api/posts/:id`: 게시글 상세
  * `POST /api/posts`: 작성 (카테고리, 제목 100자, 내용 5000자, 모집 인원 1 ~ 100명, 마감일 형식 검사)
  * `PUT /api/posts/:id`, `PATCH /api/posts/:id/status`, `DELETE /api/posts/:id`: 수정, 모집 상태 변경, 삭제 (작성자만, 아니면 403)
  * 마감일(DATE)은 문자열 그대로 받도록 설정 (시간대 변환으로 날짜가 하루 밀리는 문제 방지)
* 화면
  * 메인을 게시글 목록으로 변경: 카테고리 탭, "모집중만 보기", 글쓰기 버튼(로그인 시)
  * 게시글 상세: 작성자에게만 [모집완료로 변경 / 모집중으로 변경], [수정], [삭제] 표시, 삭제 전 확인 창
  * 게시글 작성·수정 화면 (남의 글 수정 화면 접근 차단)
* SQL 파일에 `SET NAMES utf8mb4;` 추가
  * 원인: MySQL 클라이언트의 접속 문자셋이 latin1이면 `mysql < seed.sql`로 넣은 한글이 깨져서 저장됨
* 테스트: 목록·필터, 비회원 상세 조회, 작성·수정·상태 변경·삭제, 남의 글 수정/상태 변경/삭제 차단(403), 입력값 검사
